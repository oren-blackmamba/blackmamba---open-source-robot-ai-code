# Contributing to HUMANIS

Thank you for your interest in contributing to HUMANIS!

HUMANIS is an open-source project focused on exploring the development of an AI-powered humanoid robot, combining intelligent decision-making, human-like movement research, perception, energy management, and safety systems.

Our long-term vision is to develop a humanoid robot capable of operating intelligently and efficiently, with a target of up to 12 hours of daily operation. This is a development goal, not a currently demonstrated capability.

## 1. How to Get Started

1. Read the project README.md.
2. Explore the existing source code and project structure.
3. Check the GitHub Issues page for available tasks.
4. If you have a new idea, open an issue to discuss it before making major changes.

## 2. How to Submit Code

Most contributors should use the following workflow:

1. Fork the HUMANIS repository to your GitHub account.
2. Create a new branch for your changes.
3. Implement your changes in your fork.
4. Run the relevant tests.
5. Commit and push your changes to your fork.
6. Open a Pull Request against the HUMANIS repository.
7. Explain your changes and provide testing results.

Contributors do not need direct write access to the original repository. Pull Requests allow maintainers to review proposed changes before merging them.

## 3. Development Areas

We welcome contributions in the following areas:

- AI reasoning, planning, and autonomous task execution
- Memory systems and AI agent architecture
- Computer vision and environmental perception
- Robot simulation and locomotion research
- Motion planning and balance control
- Battery management and energy optimization
- Safety monitoring and fault detection
- Testing, documentation, and developer tools

## 4. Code Quality

Please follow these principles:

- Write clear, modular, and maintainable code.
- Use descriptive names and add comments where necessary.
- Keep individual changes focused on a specific task.
- Add automated tests for new functionality when practical.
- Document new dependencies and setup requirements.
- Do not break existing functionality without explaining why.
- Never commit API keys, passwords, or private credentials.

## 5. Simulation and Physical Hardware

HUMANIS development should distinguish clearly between software simulations and verified physical hardware capabilities.

- Simulated sensor readings and movement must be labeled as simulated.
- Do not claim that a feature works on a real robot without appropriate testing.
- Do not connect experimental motion-control software to physical actuators without suitable safety checks.
- Safety-critical changes should include tests and a clear explanation of their limitations.

## 6. Energy Management

The project aims to investigate efficient electrical energy management for extended robot operation.

Contributions should use documented assumptions and measurable estimates. The 12-hour operating target must be evaluated against actual power consumption, battery capacity, workload, and hardware limitations.

## 7. Pull Request Guidelines

Each Pull Request should include:

- A short description of the problem being solved
- An explanation of the proposed solution
- A list of important files changed
- Tests performed and their results
- Known limitations or follow-up work

Large architectural changes should be discussed in a GitHub Issue before implementation.

## 8. Community Standards

Be respectful, constructive, and welcoming to contributors with different backgrounds and experience levels.

Technical disagreements should focus on evidence, implementation quality, safety, and project goals.

## 9. Getting Help

If you have questions or want to propose a feature, open a GitHub Issue and describe your idea.

We welcome contributions from AI researchers, software developers, robotics engineers, students, and open-source enthusiasts.

Thank you for helping develop HUMANIS!

Every contribution helps move the project forward.
